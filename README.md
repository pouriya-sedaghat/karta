# Karta

Karta is a self-hosted, reusable OpenStreetMap map and place-search service. Its intended dependency direction is `apps -> core -> karta`: clients use Karta's versioned HTTP API through core; Karta does not import application or core code.

Current state: **Stage 5, Iran hybrid intake, in review** on top of Stage 4 (operations and capacity), Stage 3 (opt-in online updates), Stage 2 (safe manual publication) and Stage 1 (offline map display and named-place/POI search). Stage 5 adds two opt-in intake paths that both feed the existing publication path ([ADR 0006](docs/adr/0006-stage5-hybrid-intake.md), runbook "Local intake" and "Controlled source bridge"): a **controlled source bridge** for Geofabrik's Iran extract (a downloader that alone has a route out, a signer with no network that re-verifies the bytes and holds the key, read-only HTTPS serving to Karta's fetcher) and a **protected local intake** for outages (the authenticated `karta intake submit` command and a protected-folder watcher that each create only a bounded, exact-digest authorization through a narrow credential). Stage 5 is an engineering feature implemented and tested with fixtures and local controlled services only: no Iran PBF was obtained, it was not measured on the owner's VM (tier C) and not validated on a production host (tier D). Stage 4 adds a deadline for every publication, metrics on a separate API listener, Prometheus alert rules with documented responses, backup and restore, credential rotation that keeps data, and capacity tooling ([operations](docs/operations.md), [ADR 0005](docs/adr/0005-stage4-operations.md), [licenses](docs/licenses.md)). It is verified with fixtures and the Chitgar extract only. The target host, the full-Iran capacity measurements, the Iran snapshot source, the production online source (signer and key custodian) and the service objectives are open owner decisions, so **nothing here is production-ready**. Online updates, the bridge and the local intake stay off until a deployment supplies, respectively, a reviewed source and signer key custody, or a verified landing boundary and intake credential. The active OSM snapshot (a *release*) is served as vector tiles with a local MapLibre style, Persian-capable glyphs and search. An operator publishes new snapshots **while serving** through a local inbox (or the command line): each is verified completely, its digest must be pinned or operator-authorized, it is built in an isolated candidate database and activated in one audited transaction; replaced releases stay available to pinned clients for a grace period and for rollback; an authenticated operator API (separate from the public API) gives status, rollback and cleanup. **Online updates (opt-in):** a separate fetcher process, the only one with a route out, polls a configured HTTPS source for manifests signed by a pinned Ed25519 key, downloads newer snapshots within strict limits and hands them to the publisher, which verifies them again and publishes them through the same path; no production source or signing key is configured ([ADR 0004](docs/adr/0004-stage3-online-updates.md), runbook "Online updates"). Address geocoding, reverse geocoding and routing are **not** implemented.
```bash
make secrets build up        # PostgreSQL/PostGIS, API, publisher; readiness is 503 until a publication
make import-fixture          # committed synthetic fixture (CC0), command-line publication
make wait-ready
open http://localhost:8080/demo/
make op-status               # operator view: releases, submissions, storage, online source, freshness
make test test-alerts test-integration test-browser test-offline   # test-integration includes the Stage 3, 4 and 5 suites
make up-monitoring           # optional: PostgreSQL exporter and Prometheus with the Karta alert rules
make backup                  # backups/karta-<time>; restore with make restore BACKUP=...
make intake-submit FILE=... TOKEN=secrets/NAME.token SHA256=...   # opt-in local intake (KARTA_INTAKE_DIR=/data/intake)
```

The real Chitgar Lake sample is not in Git; copy the supplied PBF and sidecar to `data/local/`, then `make reset up publish-tehran wait-ready test-browser-tehran` (inbox publication; the publisher's default region is Chitgar).

All runtime assets and data are local: after images are built, the stack needs no network (online updates are opt-in and only the fetcher uses it), and the demo page cannot contact any other host. OpenStreetMap data is licensed under ODbL; every map shows `© OpenStreetMap contributors` with a license link. Karta serves its own tiles; public OSM tile and Nominatim endpoints are not production backends. Bundled font: Vazirmatn (SIL OFL 1.1); map renderer: MapLibre GL JS (BSD-3-Clause, installed from npm with pinned integrity).
