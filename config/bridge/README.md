# Controlled source bridge configuration (Stage 5, opt-in)

The bridge (`compose.bridge.yaml`, `docs/adr/0006-stage5-hybrid-intake.md`)
reads two reviewed files from this directory, mounted read-only at
`/config/bridge`. **Nothing here is active**: the committed files are
examples (`*.example.json`). A deployment copies them, fills in its own
values after review, and names them in `.env`:

```sh
KARTA_BRIDGE_SOURCE_FILE=/config/bridge/geofabrik-iran.json
KARTA_BRIDGE_SIGNER_FILE=/config/bridge/signer.json   # the default
```

Unknown fields are refused in both files.

## Source file (bridge-acquire)

What to download, from where, and how politely. Before enabling it, confirm
the distributor's current download terms, put a real contact in
`user_agent`, and keep the poll interval in hours. Starting `bridge-acquire`
with this file downloads the **full** snapshot it names.

| Field | Required | Meaning |
| --- | --- | --- |
| `region_id` | yes | the region the deployment serves (`config/regions/<id>.json`) |
| `snapshot_url` | yes | `https://` URL of a `.osm.pbf` file; no credentials, query or fragment |
| `md5_url` | no | the distributor's `.md5` on the same host: fetched before and after each download and recorded as distributor metadata only (a mismatch discards the download, `distributor_checksum_mismatch`) |
| `distributor` | yes | recorded in the provenance sidecar the bridge writes |
| `user_agent` | yes | a descriptive name with a contact (8 to 200 characters) |
| `allowed_networks` | no | CIDR prefixes acquire may connect to although they are not public (a private mirror); every other private, loopback or link-local address is refused (ADR 0004) |
| `ca_file` | no | absolute path of the only roots trusted for the distributor (default: system roots) |
| `poll_interval` | yes | time between checks of the distributor's hints (HEAD validators, `.md5`) |
| `reverify_interval` | yes | a full download at least this often even when no hint changed (hints can be missing or stale) |
| `download_timeout`, `stall_timeout` | no | bounds on one download (2h, 2m) |
| `retry_initial`, `retry_max` | no | exponential back-off after a failed check (15m, 6h); a `429`/`503` `Retry-After` is honoured up to `retry_max` |

A filename, ETag, timestamp or `.md5` never authorizes anything: the signer
re-reads the downloaded bytes and signs only what passes Karta's own checks.

## Signer file (bridge-sign)

| Field | Required | Meaning |
| --- | --- | --- |
| `bridge_id` | yes | names this bridge in logs, provenance and operator audit |
| `keys` | yes | 1 to 4 `{id, file}` Ed25519 PKCS#8 PEM private keys; every manifest is signed with each (key rotation: add the new key, update the fetcher's `trusted_keys`, then remove the old one) |
| `manifest_validity` | yes | `expires_at - issued_at` of each manifest; must not exceed the fetcher's `max_manifest_validity` |
| `renew_before` | no | re-sign the held snapshot under a new serial this long before expiry (default: half the validity); renewal needs no distributor |

The signing key and its custodian are an owner decision: no key is
generated by this repository or its tests outside test runs. The custodian
creates it (`go run ./cmd/karta-sign keygen --out KEY.pem`, or
`openssl genpkey -algorithm ed25519 -out KEY.pem`), keeps it out of Git, and
provides it as `secrets/bridge/signing-key.pem` (or
`KARTA_BRIDGE_SIGNING_KEY_FILE`); its public key goes into the fetcher's
source file (`config/sources/README.md`, "A co-located bridge").
